# CanonFlow & ONDCFlow: Lessons Learned (MVP Implementation)

As we conclude the M0-M12 implementation of the CanonFlow Evaluator architecture, we reflect on the technical boundaries, strict functional engineering constraints, and cryptographic demands that shaped the outcome. 

Here are the key lessons learned during this highly disciplined engineering effort:

## 1. Static Enforcement Drives Purity (FsAssay)
The introduction of `FsAssay` forced us to reconsider how state and side effects are handled throughout the codebase.
- **The Cost of `mutable`:** Standard imperative algorithms (e.g., cryptographic hashing buffers, stream processing) often rely on mutable counters. `FsAssay` forces these to either be rewritten as pure recursive functions or explicitly bypassed with `// FsAssay-Ignore`.
- **Lesson:** Security and determinism require strict boundaries. Forcing developers to justify `mutable` variables ensures that unintentional state drift does not poison cryptographic assessments.

## 2. Platform Independence & Cryptography (WASM vs Native)
In Phase M10, we encountered the limitations of the standard .NET `SHA256.Create()` implementation when transpiling F# to WebAssembly (WASM) via Fable.
- **The Issue:** Browsers rely on the asynchronous WebCrypto API, while CanonFlow’s `Digest.fs` relies on synchronous computations to maintain a pure, non-blocking algebra.
- **The Fix:** We had to implement a pure F# SHA-256 algorithm to guarantee that our hashing was completely independent of platform-specific cryptography bindings (like OpenSSL or Windows CNG), ensuring that `assessment.cff` generated in WASM is byte-for-byte identical to the one generated by the .NET 10 CLI.

## 3. The 4-State Verdict Algebra is Uncompromising
The requirement to use a strictly defined bounded join-semilattice (`Pass`, `Inconclusive`, `Fail`, `ToolFailure`) fundamentally changed the architecture of ONDCFlow.
- **The Issue:** Early attempts to "count" passing rules or default to `Pass` when no errors were found led to the *Vacuous Truth hazard*.
- **The Fix:** We implemented a strict precedence law (`ToolFailure` > `Fail` > `Inconclusive` > `Pass`). If an evidence trace is missing, the verdict is unequivocally `Inconclusive`, preventing applications from achieving "Conformance by Absence."

## 4. Separation of Concerns (The Ownership Law)
It was critical to prevent `CanonFlow.Assurance` from becoming bloated with framework-specific or IO-bound code.
- **The Issue:** It is tempting to inject `TimeProvider`, `ILogger`, or `Docker` dependencies straight into the core domain.
- **The Fix:** We enforced the *Ownership Law*. `CanonFlow.Assurance` owns pure semantics. `CanonFlow.Profile.ONDC` owns protocol structures. `CanonFlow.Evaluator` orchestrates the execution. `CanonFlow.Reports` generates the offline artifacts. This prevents dependency entanglement and keeps the core logic mathematically provable.

## 5. Security & Transparency Cannot be Self-Awarded
Phase M12 taught us that technical enforcement must be paired with governance.
- **The Issue:** Generating a cryptographically signed receipt is useless if anyone can generate one declaring themselves "ONDC Certified".
- **The Fix:** We decoupled the cryptographic *seal* from the *assessment result*. Furthermore, we deferred "Certification" to external authorities using `source.lock.json` and a gated GitHub Action (`certify.yml`), strictly preventing self-awarded certificates in the MVP.
